# Architecture

## Data first

`scripts/prepare_data.py` reads GeoPackage metadata with read-only SQLite and spatial records with Pyogrio/GeoPandas. It validates required fields, numeric voltage, flags, EPSG:4326, geometry families, valid/nonempty geometry, coordinate bounds and original IDs before classification. It applies the exact predicates from `DATA_FILTER_SPEC.md`, quarantines conflicting source flags, and records exclusions rather than expanding scope from names or string voltage tags.

The pipeline normalizes properties, measures line geometry with WGS84 `pyproj.Geod`, normalizes polygon winding and rounds existing line/polygon coordinates to seven decimals. The original three GeoJSONs remain byte-identical. Eligible point-only candidates retain full source coordinate precision; their voltage stays null. Representative symbols are generated inside the published footprint with parent IDs and a non-inventory role. The pipeline validates geometry and original-record IDs separately from symbol linkage before writing. UTF-8 JSON uses explicit nulls, rejects NaN/Infinity, and uses temporary-file replacement. The source is hashed before and after; no source writes occur. Individual files are replaced atomically; use all nine outputs from one run together. No deployment is performed by preprocessing.

Historic audit comparisons live in `scripts/expected-audit.json`. A mismatch emits exact differences under internal QA and stops before publication unless explicitly overridden. QA artifacts contain the excluded line/polygon ID inventory, point-substation review layer and status-conflict quarantine. The public report is aggregate only. Metadata is computed, versioned by source/pipeline, deterministic, and includes per-GeoJSON checksums.

`scripts/substation_matching.py` evaluates all 68×2,753 point/polygon pairs, retaining intersection/proximity/ID/name/reference/attribute evidence. Policy-supported matches, uncertain associations and distinct candidates are recorded for every point. Matched/uncertain and role/function-held points never enter the optional point dataset. Full reproducible JSON/CSV stay under internal QA; public metadata contains aggregate results/policy. See `SUBSTATION_MATCHING.md`.

`scripts/check_public_data.mjs` is the build-time guard. It needs no raw data or Python; it checks all nine generated files, version/hash/count consistency, unique original IDs, scope, one-to-one symbol/parent linkage, symbol non-inventory roles and nonpublic-file exclusions.

## Vue application

- `services/assetData.ts`: validated fetches, cached successful/in-flight requests and retryable failures. Base lines, primary polygons, power plants, representative symbols and summary load once. Polygon-review and point-only candidates are independently lazy.
- `composables/useAssetFilters.ts`: data/error/loading state, filter state, on-demand candidate loading and computed selection/counts. Large feature arrays use shallow refs.
- `utils/filterAssets.ts`: pure layer, status, voltage and name/ref/operator/ID filtering; independent candidate visibility; missing-voltage control; geometry bounds.
- `types/assets.ts`: schemas used by current inventory records, representative points, filters and metadata. The unused speculative planned-asset interface was removed; future authoritative data needs a separately reviewed schema.
- `AppHeader`, `InventorySummary`, `FilterSidebar`: branding and the About action, computed KPIs and accessible controls. The redundant Inventory header link and its active-navigation styles were removed.
- `utils/substationPresentation.ts`: representative-parent filtering, canonical deduplicated rendered-record counts and `selectedMapLegend`, a key derived from filtered original features. Representative symbols never enter the selected inventory array or add legend categories.
- `MapCanvas`: dynamically imported MapLibre GL JS 6, original-record source plus filtered representative-symbol source. Voltage-colored line styling/filtering is unchanged. Below zoom 10, polygon records use interior symbols; at local zoom, original primary/review footprints replace symbols. Eligible original points use distinct pink outlined symbols when enabled. All representations select the original feature ID and preserve counts.
- `AssetTable`: paginated searchable records, keyboard buttons and selection shared with the map.
- `AssetDetailsDrawer`: source-only details, fallback-label and uncertainty notices, geodesic measurement meaning and explicit unknowns. It renders through a named MapCanvas slot as a floating card inside the map frame rather than as a fixed viewport overlay or docked column. A separate scrollable attributes region supports keyboard scrolling; the header/close control stays visible. Escape closes details and returns focus.
- `DataProvenanceDialog`: native modal/focus handling, source attribution, coverage and source-status caveats. About and feature-detail close buttons use centered SVG icons with zero button padding and fixed dimensions. The footer contains only centered attribution links; duplicate branding and the Coverage action were removed. The download section and dataset links have been removed. Full ODbL/OpenInfraMap notices remain in the footer and publication metadata; the map retains concise provider and OSM copyright links. Static data requests remain public and are not protected by removing UI links.

The five KPI cards use compact padding/typography and reduced title spacing. The Filters button precedes search in both the DOM and visual order, grouped with a small gap instead of an auto margin. The same deduplicated original-feature array drives the map, legend, list and five KPI counts, with separate point-only and polygon-review metrics. `FilterSidebar` no longer receives summary metadata or displays source totals. It contains Layers, Voltage and OSM status controls with short candidate/unknown-voltage hints. Sidebar rows use 28 px desktop / 34 px mobile minimum heights; section padding, legend gaps and helper-note spacing are reduced without affecting popup or basemap-picker layouts. Source totals remain in metadata and About; the cards/list report matching records. Viewport counts canonicalize `represented_feature_id` or `feature_id` across sources/layers/tile fragments; they are not national totals or exact geometric intersections. Changes close details if a record no longer matches. Unknown-voltage filtering applies explicitly to both candidate groups. Candidate data load failures are separately retryable.

## Power-plant context

Preprocessing reads `power_plant` as a fourth spatial layer. A separate `expected-power-plant-audit.json` reports exact QA differences without rewriting the historic grid audit. All 643 valid footprints retain precision and source tags; an interior `plant_representative_point` is derived and checked for containment. Schema-v3 metadata includes separate plant totals and presentation policy.

The repository loads plants with the base inventory and validates footprint geometry/unknown units. `powerPlants` is on by default. Status and search apply, but voltage skips plants because no voltage field exists. Counts and legend state have separate plant categories. MapLibre uses an uncounted `plant-symbols` source with parent IDs and locally drawn diamond icons below zoom 10; original boundaries appear at local zoom. Construction symbols are hollow and footprints dashed. Selection resolves the original record. Viewport queries canonicalize IDs against the current selection and refresh after source updates; symbol fading is disabled to avoid stale markers/counts during rapid filtering. Basemap reloads restore plant images, sources and layers. See [POWER_PLANTS_REPORT.md](POWER_PLANTS_REPORT.md).

## Map delivery and failure behavior

The default inline raster style uses `https://tile.openstreetmap.org/{z}/{x}/{y}.png`, visible OpenStreetMap attribution and standard browser caching/referrer behavior. No prefetch or offline tile download is provided. `VITE_BASEMAP_STYLE_URL` allows another lawful MapLibre style; its provider attribution is preserved alongside source attribution. Vite public variables are visible to all users, so secrets are unsuitable.

`utils/basemaps.ts` defines OpenStreetMap, the user-supplied Google Satellite tile endpoint, plain background and optional configured style. `MapBasemapPicker.vue` provides a compact radio popover with outside-click/Escape dismissal and focus restoration. Whole-row clicks select previews, text and padding; preventing pointer-down focus loss keeps the popup mounted until selection. Native radio change events retain keyboard navigation. A full style reload reattaches the current filtered inventory/symbol sources and selected feature, while preserving camera and Vue filter state. Google imagery shows **© Google Maps | © OpenStreetMap contributors**. Attribution uses `white-space: nowrap` without percentage width caps so the full credit stays on one line, including narrow mobile layouts. Shared `OSM_ATTRIBUTION` text lets MapLibre deduplicate identical basemap/inventory credits for the OSM style; plain backgrounds retain the inventory credit. Full OpenInfraMap/ODbL links remain in the footer rather than repeating inside the map. Satellite-only line casing improves contrast without changing features or filters. Direct-endpoint service limitations are documented in README; this is not an official Google key/session integration.

`MapLegend.vue` starts collapsed and keeps its state through style/zoom changes. Its key follows the current selection: only represented line voltages, substation categories and applicable line patterns appear; no matches produces an empty message. Line colors represent kV, while neutral solid/dashed/dotted samples explain status patterns. A separate amber sample describes construction-tagged primary substations, as a circle below zoom 10 or a footprint outline above it. Longer geometry/counting explanations stay in About/details. The single extent control uses a frame SVG icon to fit the active filtered records, with a tooltip and accessible name. Camera moves respect reduced-motion preference; minimum zoom 2 accommodates narrow screens. Five matching-record metrics remain on the dashboard, including the separate plant count. `AppHeader.vue` retains the supplied full-color MENTARI logo.

Map tools are positioned inside `.map-body`, above the MapLibre canvas in an isolated stacking context. The external toolbar is removed. The extent/basemap group has z-index 4; its popover sits above the legend and native map controls. Native zoom controls are offset below the group. Main content is centered with a 1360 px maximum width and 24 px desktop, 16 px tablet and 12 px mobile side padding. The more compact map frame uses `clamp(520px, 66vh, 720px)` on desktop, `clamp(500px, 64vh, 680px)` on tablet and `clamp(480px, 62svh, 620px)` on mobile. The sidebar is narrower and can be hidden with the Filters control on every screen size, without changing active filters. It starts open above 720 px and closed on mobile.

The full-size canvas stays behind a floating 340 px details card, inset below the top toolbar and left of the zoom controls. A named CSS container query at 760 px map width moves the card to the lower map area with margins above copyright; it does not create a separate row or column. The card has rounded corners, a shadow, a fixed close header and an independently scrolling body. The repeated status footer is omitted; source attributes and inline unknown-unit/date notices remain. Camera fitting measures the actual card bounds and adds space on the right or bottom so the selected geometry remains visible. Closing the card recenters the feature. ResizeObserver tracks container dimensions independently of MapLibre's native window listener, ensuring responsive refits still occur if MapLibre already resized its canvas. The record table stays below the map.

`style.css` defines shared MENTARI blue/red, surface, text, border, shadow and motion tokens. Header, cards, tables, dialogs, legend and basemap picker use the same palette. MapLibre's plain background matches the cool neutral canvas color; voltage and asset-symbol colors are unchanged. Plus Jakarta Sans is a local variable WOFF2 asset, preloaded by `index.html` and loaded with `font-display: swap`; no external font service is needed at runtime. Short color/shadow transitions and panel entrance animations respect `prefers-reduced-motion`. Font provenance, checksum and bundled OFL notice are recorded in `FONT_SOURCES.md`.

MapLibre 6 requires a bundled worker URL. `MapCanvas.vue` imports `maplibre-gl-worker.mjs?worker&url` and sets it before constructing the map, following the [official Vite integration](https://maplibre.org/maplibre-gl-js/docs/). This makes the worker and its imports available in both dev and production builds.

Inventory rendering/viewport counts do not wait for external raster requests. Map errors or tiles still pending after 12 seconds offer a **Use plain background** action; overlays and records remain usable. WebGL initialization failure leaves the searchable list/details available with an explicit message. Missing or malformed inventory files show a retryable filename-specific error; mixed dataset counts show a redeployment message.

## Performance and hosting

The six intended GeoJSONs total 8,887,904 bytes. Power plants add 1,111,875 bytes and preserve original coordinates; interior display coordinates are embedded in each record rather than published as another inventory dataset. Review polygons (450,635 bytes) and point-only candidates (36,376 bytes) are lazy; representative display symbols add 490,830 bytes without adding inventory records. MapLibre remains a separate lazy chunk, and a 20-row table limits DOM work. Browser tests cover actual symbols/footprints, zoom transitions, selection, candidate retries, unknown voltage and mobile controls. No new dependency, backend, database, object store, PMTiles or analytics was added. This enhancement is local-only; hosting configuration is unchanged.

The production build reports a MapLibre vendor chunk above Vite's 500 kB warning threshold (about 1.10 MB, 298 kB gzip), plus a bundled worker of about 519 kB. The warning is retained and documented. Splitting MapLibre internals would add complexity without reducing bytes needed by the map; no threshold was raised to hide it. Further measurements on slower/mobile devices should precede architectural changes.

Vercel builds the existing Vite app to `dist/`; only static artifacts are served. Preprocessing remains local. No router or serverless function was added, so no catch-all rewrite is needed. Data paths revalidate to avoid holding stable filenames indefinitely. See `DEPLOYMENT.md`.
